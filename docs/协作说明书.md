# 智讯通 · 小白协作说明书

> 给组长和组员一起看。看完应能回答三句话：  
> **组长已经做好了什么？我该做什么？做完怎么接到一起？**

---

## 一、先用大白话理解整个项目

把「智讯通」想成一条工厂流水线：

```
网上新闻  →  清洗入库  →  中台调度  →  AI 分析 / 查公司资料  →  网页展示 + 钉钉/邮件通知
   ↑            ↑           ↑              ↑                        ↑
  成员B        成员B       组长A         成员C + 成员D              成员E
```

老师要求的技术对应关系：

| 技术 | 谁主要碰 | 干什么 |
|---|---|---|
| 爬虫 + MySQL | 成员 B | 把网页变成数据库里的新闻 |
| FastAPI | 组长 A | 统一入口，别人都通过它说话 |
| RAGFlow | 成员 C | 公司内部 PDF/Word 问答，带出处 |
| Dify | 成员 D | AI 工作流：问答、周报、风险研判 |
| 前端 + 钉钉 + 邮箱 | 成员 E | 给人看、给人发消息 |

**一句话：** 组长搭好了「总开关和插座」；组员各自做自己的「电器」；最后把插头插上就通电。

## 二、组长（你）已经做完了什么

你现在不是从零开始。仓库里已经有能跑的中台。

### 2.1 你已经交付的东西

1. **统一约定（契约）**  
   - 大家字段怎么写、接口叫什么名字，已经定死  
   - 位置：`packages/schemas`、`docs/openapi.yaml`、`docs/events.md`

2. **FastAPI 中台（总开关）**  
   - 位置：`services/api`  
   - 已经能：登录、启动采集、查新闻、问答、生成周报、风险研判、发通知  
   - 打开地址：http://127.0.0.1:8000/docs

3. **假组员（Mock）**  
   - 组员还没写完时，中台用「假数据 / 假服务」也能跑通全流程  
   - 所以你现在就能独自演示，不卡组员进度

4. **演示种子数据**  
   - 里面有一条「汽车召回」新闻，答辩专门用来演示高风险预警

### 2.2 你怎么自己验证「中台能用」

1. 启动中台（见仓库 `README.md`）
2. 打开 http://127.0.0.1:8000/docs
3. 调用 `POST /api/auth/login`，账号密码：`demo` / `demo123`
4. 复制返回的 `access_token`
5. 点右上角 **Authorize**，粘贴 token
6. 按顺序点：
   - `POST /api/crawler/start`，内容填 `{"source_id":"demo_recall"}`
   - `GET /api/news?category=risk`
   - `POST /api/alert/evaluate`，填上一步新闻的 `id`
   - `POST /api/notify/dingtalk`，填返回的 `alert_id`

能跑通，说明你的中台没问题。

### 2.3 组长现在的日常职责（很简单）

- 保护契约：别人想改字段名，必须找你同意  
- 帮组员对接：他们做完后，你改配置「把假插头换成真插头」  
- 最后联调：保证「召回新闻 → 高风险 → 钉钉/邮件」一条线跑通

## 三、四个组员分别做什么（只看自己那一段）

### 成员 B：数据采集（爬虫）

**你负责的文件夹：** `services/crawler`、`fixtures/html`

**你要完成的事（大白话）：**

1. 从 3 个网站（或练习用的本地 HTML）抓新闻  
2. 清洗、去重  
3. 存进 MySQL 的 `news` 表  
4. 给组长一个开关函数：`run_crawl(source_id)`

**三个数据源名字必须用这两个词（不要自己改名）：**

- `miit_policy`：政策  
- `ev_news`：行业新闻  
- `oem_news`：车企动态  

**你怎么算做完了：**

- 点一次采集，控制台能看到类似：抓到多少、新增多少、重复多少  
- 数据库 `news` 表里有数据  
- 同一批数据再跑一次，新增应接近 0（说明去重生效）

**你现在可以先不管：** Dify、RAGFlow、前端、钉钉。

**对接组长时：** 告诉组长「我的 `run_crawl` 写好了」。组长把配置改成 `CRAWLER_MODE=local`。

### 成员 C：企业知识库（RAGFlow）

**你负责的文件夹：** `services/rag`、`fixtures/docs`

**你要完成的事（大白话）：**

1. 把 RAGFlow 跑起来  
2. 上传公司资料（至少准备一份《X1产品说明书》，里面写死：最大日处理能力 6800 件，第 13 页）  
3. 做好「提问 → 检索 → 带出处返回」

**你怎么算做完了：**

- 问：「X1 最大日处理能力是多少？」  
- 能答出 6800，并显示来自说明书第几页  
- 不走知识库时答不出来（用来对比，答辩很加分）

**你现在可以先不管：** 爬虫、钉钉、前端页面美化。

**对接组长时：** 告诉组长 RAGFlow 地址和接口。组长改 `RAG_MODE=http`。

---

### 成员 D：AI 工作流（Dify）

**你负责的文件夹：** `services/ai`

**你要完成的事（大白话）：**

在 Dify 里搭 3 条流水线（名字别改）：

1. `wf_knowledge_qa`：知识问答  
2. `wf_industry_brief`：近 7 天行业周报（固定六个标题）  
3. `wf_risk_alert`：判断新闻风险等级（低/中/高/紧急）

周报六个标题必须是：

1. 本周行业概况  
2. 重要政策  
3. 重点企业动态  
4. 技术进展  
5. 市场动态  
6. 趋势与建议  

**小技巧：** 标题里出现「召回」时，风险至少判为高（答辩稳）。

**你怎么算做完了：**

- 能在 Dify 界面打开节点图给老师看  
- 对「召回」新闻能输出高风险 JSON（格式见 `docs/events.md`）

**对接组长时：** 告诉组长 Dify 地址和 API Key。组长改 `DIFY_MODE=http`。

### 成员 E：前端 + 钉钉 + 邮件

**你负责的文件夹：** `apps/web`、`services/notify`

**你要完成的事（大白话）：**


**你怎么算做完了：**

- 页面能登录、能看到新闻和预警  
- 钉钉群真的收到消息（或开发阶段用控制台/Mailhog 看到）

**对接组长时：**  
- 前端：把接口地址指向 `http://127.0.0.1:8000`  
- 通知：告诉组长 webhook；组长改 `NOTIFY_MODE=http`

## 四、做完之后怎么整合（最重要）

### 4.1 先记住一个原则

```
组员开发阶段：各自独立做，组长中台用「假服务」也能演示
最后 2～3 天：把假服务换成真服务，做联调
```

现在配置默认是「全假」：

```
CRAWLER_MODE=mock
RAG_MODE=mock
DIFY_MODE=mock
NOTIFY_MODE=log
```

意思是：爬虫、知识库、AI、通知都还是组长的替身在干活。

### 4.2 组员交作业后，组长怎么「换插头」

在仓库根目录或 `services/api` 下放一个 `.env`（可复制 `.env.example`），按人逐步改：

| 谁完成了 | 组长改什么 | 改成什么 |
|---|---|---|
| 成员 B 完成 | `CRAWLER_MODE` | `local`（或他的 `http` 地址） |
| 成员 C 完成 | `RAG_MODE` | `http`，并填 `RAG_BASE_URL` |
| 成员 D 完成 | `DIFY_MODE` | `http`，并填 `DIFY_BASE_URL`、`DIFY_API_KEY` |
| 成员 E 完成通知 | `NOTIFY_MODE` | `http`，并填 `DINGTALK_WEBHOOK` |
| 成员 E 完成前端 | 前端配置 | API 地址指到 `http://127.0.0.1:8000` |

**可以一个人一个人换，不用等五个人同时完成。**  
例如：B 先完成，就先换成真爬虫；C/D/E 仍可继续用假的。

### 4.3 整合验收：只测这一条线

不要测一百个功能。全组只认准这条答辩主线：

```
1. 启动采集（最好用召回新闻）
2. 新闻列表能看到「召回」
3. 风险研判结果 = high
4. 钉钉收到提醒（或控制台/邮件能看到同样内容）
5. （加分）再问一句 X1 日处理能力 = 6800，并有出处
```

这条线通了，项目就算「整合成功」。

### 4.4 出了问题怎么查（小白排错）

| 现象 | 先问谁 | 常见原因 |
|---|---|---|
| 登录失败 | 组长 | 中台没启动，或账号不是 demo/demo123 |
| 采集没数据 | 成员 B / 组长 | B 还没接上，或还在 mock 且种子没跑 |
| 问答没有出处 | 成员 C | RAGFlow 没起，或文档没入库 |
| 风险一直是低 | 成员 D | Prompt/规则没把「召回」抬成高风险 |
| 钉钉没消息 | 成员 E / 组长 | webhook 错，或还在 `NOTIFY_MODE=log`（只打日志） |
| 前端空白/401 | 成员 E | 没带 token，或 API 地址不对 |

## 五、一张图看懂「谁依赖谁」

```
成员 B 产出：news 表里的新闻
        ↓
组长 A 中台：对外提供统一 API
        ↓
   ┌────┴────┐
成员 C 查资料   成员 D 做研判/周报
   └────┬────┘
        ↓
成员 E：网页展示 + 钉钉/邮件发出去
```

答辩时别说「我们五个人各做一块」。  
要说：**我们是一条流水线，五段工序。**

## 六、建议时间安排（10 天版，可压缩）

| 天数 | 大家干什么 |
|---|---|
| 第 1 天 | 组长发契约；每人认领目录；中台能跑 |
| 第 2～5 天 | 各自开发；互不阻塞；组长继续完善中台演示 |
| 第 6～7 天 | 有人完成就先对接一个人 |
| 第 8～9 天 | 全员联调「召回闭环」 |
| 第 10 天 | 预答辩：每人 3 分钟 + 最后 4 分钟一起演示闭环 |
